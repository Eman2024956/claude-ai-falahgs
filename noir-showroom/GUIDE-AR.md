# الدليل: من طلب المستخدم إلى مشهد ثلاثي الأبعاد

هذا الدليل يشرح كل خطوة يمر بها الطلب النصي حتى يصبح صفحة ثلاثية الأبعاد تعمل في المتصفح، مع اسم الملف والدالة المسؤولة عن كل خطوة.

## الفكرة الأساسية أولاً

**النص لا يتحول إلى مجسّم مباشرة.** لا يوجد ذكاء اصطناعي يرسم سيارة من الكلمات، ولا يُولَّد كود JavaScript جديد لكل طلب.

ما يحدث هو:

1. النص يُحوَّل إلى **خطة** (ملف JSON) تصف المشهد والحركة بالأرقام والأسماء.
2. الخطة تُفحص للتأكد أنها تحتوي فقط على أشياء معروفة ومسموحة.
3. **مشغّل ثابت** (runtime) يقرأ الخطة ويبني المشهد من قطع مكتوبة مسبقاً.

أي أن كلمة "car" في الطلب لا تصنع سيارة، بل **تختار** اسم مجسّم موجود في سجل المشغّل اسمه `coupe`. شكل السيارة نفسه مكتوب مسبقاً كمعادلات في `src/runtime/car.js`.

```
الطلب النصي ──► المخطِّط ──► الخطة JSON ──► الفحص ──► المشغّل ──► الصفحة
brief.txt      planner/     scene-plan.json  validate.js  src/runtime/  WebGL
```

## الخطوة 1: الطلب النصي

**الملف:** `plan/brief.txt`

```
Create a premium black luxury-car website. Put the car inside a dark cinematic
showroom with marble flooring, soft volumetric-looking lighting, floating
particles and a camera that slowly moves around the car. When the user scrolls,
transition from the showroom to the product specifications.
```

هذا هو المدخل الوحيد. لتغيير الموقع تعدّل هذا النص ثم تشغّل:

```bash
npm run plan
```

## الخطوة 2: المخطِّط يحوّل النص إلى خطة

**الملفات:** `planner/compile.mjs` و `planner/rules.mjs` و `planner/content.mjs`

المخطِّط **قائم على قواعد** (ليس نموذج لغة). يعمل هكذا:

### 2.1 خطة أساسية

الدالة `basePlan()` في `compile.mjs` تنشئ خطة كاملة وصالحة لاستوديو بسيط محايد. هذا ما تحصل عليه لو كان الطلب فارغاً.

### 2.2 تطبيق القواعد

كل قاعدة في `rules.mjs` لها ثلاثة أجزاء:

```js
{
  intent: 'floor',                                    // اسم النية
  pattern: /\b(?:(black|white|dark|light)\s+)?marble(?:\s+floor(?:ing)?)?\b/i,  // العبارة التي تبحث عنها
  sets: ['scene.floor'],                              // ما تغيّره في الخطة
  apply(plan, match) { /* تكتب القيم في الخطة */ },
}
```

الدالة `compile()` تمر على القواعد واحدة واحدة. إذا وُجدت العبارة في النص، تُنفَّذ `apply` وتُسجَّل النية.

نتيجة طلبك (10 قواعد طابقت، ولا شيء بقي بلا تفسير):

| العبارة في الطلب | النية | ما كتبته في الخطة |
| --- | --- | --- |
| `luxury-car` | subject | `scene.subject.asset = "coupe"` |
| `black` | paint | `scene.subject.paint.color = "#050507"` |
| `premium` | tone | لون ذهبي `#c8a46a`، طلاء لامع، حلقة ضوء في الأرضية |
| `dark cinematic showroom` | environment | صالة نصف قطرها 24 م، ضباب، ألوان الصفحة الداكنة |
| `marble flooring` | floor | رخام أسود، انعكاس 0.62 |
| `soft volumetric-looking lighting` | lighting | 7 أضواء: 3 صناديق ضوء، 3 كشافات بأعمدة ضوء، ضوء محيط |
| `floating particles` | particles | 1400 جزيء |
| `camera that slowly moves around` | camera | `camera.orbit.speed = 4` درجات في الثانية |
| `scrolls` | scroll-driver | طول التمرير 6.5 شاشات |
| `transition from the showroom to the product specifications` | specifications | 12 مسار حركة + أقسام المواصفات |

لاحظ كلمة `slowly`: القاعدة تترجمها إلى الرقم 4. لو كتبت `quickly` لأصبحت 14.

### 2.3 ما لا يُفهم يُبلَّغ عنه

بعد القواعد، يقسّم `compile()` النص إلى جمل صغيرة. أي جملة لم تلمسها أي قاعدة تُكتب في `meta.unresolved`. المخطِّط **لا يخترع** شيئاً لم يفهمه.

### 2.4 النصوص والأرقام

اسم السيارة والمواصفات (القوة، الطول...) لا تأتي من الطلب، لأن الطلب يصف الشكل لا المنتج. مصدرها `planner/content.mjs`، وهي بيانات تجريبية لسيارة خيالية.

### 2.5 الطلب بالعربية: القاموس

إذا احتوى الطلب على حروف عربية، يُقرأ بالقاموس بدل الأنماط الإنجليزية. النتيجة هي المفاهيم نفسها، فتُطبَّق القواعد نفسها.

**الملفات:** `planner/lexicon.ar.json` (المفردات) و `planner/arabic.mjs` (المترجم والتدقيق)

```bash
npm run plan:ar     # يحوّل plan/brief.ar.txt إلى plan/scene-plan-ar.json
```

ثم افتح `?plan=scene-plan-ar`.

مراحل المترجم الخمس:

1. **التوحيد** (`normalise`): حذف التشكيل، وتوحيد الهمزات (أ إ آ ← ا) والياء (ى ← ي) والتاء المربوطة (ة ← ه).
2. **التجزئة** (`tokenise`): تقسيم النص إلى كلمات، مع حفظ موضع كل كلمة ورقم جملتها. ثم `forms` تنزع اللواصق (و، ف، ب، ل، ك، ال، وتنوين الألف) فتطابق "وبالسيارة" كلمة "سيارة".
3. **البحث في القاموس** (`scan`): مطابقة الكلمات والعبارات، الأطول أولاً ("صالة عرض" قبل "صالة").
4. **الربط:** كل صفة (لون، مظلم/فاتح، ناعم، سرعة) تُعطى لأقرب شيء تصفه في الجملة نفسها. "سيارة حمراء على رخام أبيض" ← الأحمر للسيارة والأبيض للرخام.
5. **التدقيق:** كل ما يلي يُكتب في `meta.unresolved`:
   - كلمة غير موجودة في القاموس، مع اقتراح إن كان الفرق حرفاً واحداً: «برخم» (هل تقصد «رخام»؟)
   - تعارض: لونان للسيارة، ويُستخدم الأول.
   - صفة بلا موصوف، أو حركة كاميرا غير مدعومة.

النفي مفهوم: "بدون جزيئات" يلغي الجزيئات، ويظهر في `meta.intents` بقائمة `sets` فارغة.

القاموس ملف بيانات فيه أربعة أقسام: `things` (الأشياء)، `modifiers` (الصفات)، `negation` (أدوات النفي)، `ignore` (كلمات لا تحمل معنى للمشهد مثل "في" و"أريد"). لإضافة مرادف تكفي إضافته إلى القائمة المناسبة.

## الخطوة 3: الخطة

**الملف:** `plan/scene-plan.json`

الخطة بيانات فقط. أجزاؤها الستة:

| الجزء | يصف |
| --- | --- |
| `meta` | الطلب الأصلي، وأي عبارة أنتجت أي جزء (`intents`)، وما لم يُفهم (`unresolved`) |
| `theme` | ألوان الصفحة |
| `scene` | الصالة، الأرضية، المجسّم، الأضواء، الجزيئات |
| `camera` | العدسة والدوران التلقائي |
| `timeline` | مسارات الحركة المرتبطة بالتمرير |
| `content` | الأقسام والنصوص والأرقام والروابط |

مثال: السيارة في الخطة هي هذا فقط:

```json
"subject": {
  "asset": "coupe",
  "paint": { "color": "#050507", "metalness": 0.9, "roughness": 0.22, "clearcoat": 1 },
  "glassColor": "#07080a",
  "headlightColor": "#eaf2ff",
  "taillightColor": "#ff1a22",
  "rotationY": 0
}
```

اسم المجسّم + ألوان + خصائص الطلاء. لا توجد نقاط ولا مثلثات في الخطة.

مثال: كشاف بعمود ضوء:

```json
{ "id": "key", "type": "spot", "color": "#ffe6c4", "intensity": 26,
  "position": [2.6, 7, 2.2], "target": [0.6, 0, 0], "angle": 17, "beam": { "opacity": 0.34 } }
```

مثال: مسار حركة (زاوية الكاميرا حسب نسبة التمرير من 0 إلى 1):

```json
{ "target": "camera.azimuth",
  "keys": [ { "at": 0, "value": 52 }, { "at": 0.28, "value": 66 },
            { "at": 0.52, "value": 0 }, { "at": 0.755, "value": -52 }, { "at": 0.96, "value": -74 } ] }
```

## الخطوة 4: الفحص

**الملفات:** `plan/scene-plan.schema.json` و `plan/validate.js`

الفحص يجري مرتين: في المخطِّط قبل كتابة الملف، وفي المتصفح قبل بناء أي شيء (`src/main.js`).

يرفض الفحص:

- أي خاصية غير معروفة.
- أي رقم خارج المدى المسموح (مثلاً عدد الجزيئات أكثر من 20000).
- أي هدف حركة غير موجود في القائمة الثابتة.
- أي رابط غير رابط داخلي `#section` أو `mailto:`.
- مسار حركة يشير إلى ضوء غير موجود، أو مفاتيح زمنية غير مرتبة.

جرّبتُ خطة معدَّلة عمداً، وهذه رسالة الرفض:

```
plan.scene.subject.onload: unknown property
plan.timeline.tracks[12].target: "window.location" is not allowed here
plan.content.sections[0].actions[0].href: "javascript:alert(1)" is not allowed here
```

هذا هو سبب الأمان: الخطة لا يمكن أن تحمل كوداً، والمشغّل لا ينفّذ أي شيء منها.

## الخطوة 5: المشغّل يبني المشهد

**الملف الرئيسي:** `src/runtime/index.js` (الدالة `mount`)، والمكتبة هي **Three.js r170** فوق WebGL.

`mount(plan)` يقرأ الخطة وينادي دالة بناء لكل جزء:

| جزء الخطة | دالة البناء | الملف |
| --- | --- | --- |
| `scene.subject` | `ASSETS[plan.scene.subject.asset]` أي `buildCoupe` | `car.js` |
| `scene.environment` | `buildRoom` | `stage.js` |
| `scene.lights` | `buildLights` | `stage.js` |
| `scene.floor` | `buildFloor` | `stage.js` |
| `scene.particles` | `buildParticles` | `stage.js` |
| `timeline` | `createTimeline` | `timeline.js` |
| `content` | `buildContent` | `content.js` |

السطر الذي يربط الاسم بالمجسّم:

```js
const ASSETS = { coupe: buildCoupe };
const subject = ASSETS[plan.scene.subject.asset](plan.scene.subject, plan.theme);
```

### 5.1 كيف يُبنى مجسّم السيارة (`car.js`)

السيارة تُحسب بالمعادلات عند فتح الصفحة. المحاور: `x` للأمام، `y` للأعلى، والوحدة متر.

1. **ثلاثة منحنيات تحدد الشكل على طول السيارة:**
   - `deckLine(x)`: ارتفاع الغطاء والسطح الخلفي، منحنى يمر بثماني نقاط تحكم.
   - `sillLine(x)`: ارتفاع أسفل الهيكل.
   - `planWidth(x)`: نصف العرض كما يُرى من الأعلى (يضيق عند المقدمة والمؤخرة).
2. **المقطع العرضي:** `bodyPoint(x, theta)` تعطي نقطة على محيط الهيكل. الشكل "مربع بزوايا مستديرة" (superellipse)، أكثر تربيعاً في الأسفل وأكثر استدارة في الأعلى، مع ميل الأكتاف للداخل.
3. **أقواس العجلات:** داخل `bodyPoint`، أي نقطة قريبة من مركز عجلة تُدفع إلى الداخل لتكوّن تجويف العجلة.
4. **السطح:** `loft()` تحسب 280 مقطعاً × 80 نقطة = 22400 نقطة، وتربط كل أربع نقاط متجاورة بمثلثين، ثم تحسب اتجاهات السطح (normals) للإضاءة.
5. **المقصورة الزجاجية:** سطح ثانٍ بالطريقة نفسها عبر `cabinPoint` و `roofLine`.
6. **المصابيح والشبك:** `wrapBand()` تقتطع شريطاً من سطح الهيكل نفسه بين ارتفاعين، يلتف حول المقدمة أو المؤخرة، ويُرفع 6 مم عن السطح.
7. **العجلات:** `buildWheel()` تبني الإطار بتدوير مقطع جانبي (`LatheGeometry`)، ثم الجنط و10 أذرع وقرص المكابح.
8. **الألوان من الخطة:** لون الطلاء والزجاج والمصابيح تُقرأ من `scene.subject`.

### 5.2 الصالة والإضاءة (`stage.js`)

- **`buildRoom`:** جدار أسطواني مضاء من الأسفل، سقف، وشرائح ضوء عمودية على الجدار.
- **`buildLights`:** لكل ضوء في الخطة حسب نوعه:
  - `softbox`: لوح مضيء في السقف، ويُخبز أيضاً في خريطة الانعكاسات (`PMREMGenerator`). هذه هي الخطوط اللامعة على الطلاء الأسود.
  - `spot`: كشاف حقيقي + مخروط شفاف بشيدر (shader) يتلاشى عند الحواف، وهو "عمود الضوء" الذي يعطي المظهر الحجمي.
  - `ambient`: ضوء عام خافت.

### 5.3 أرضية الرخام (`buildFloor`)

- إضافة `Reflector` من Three.js ترسم المشهد مرة ثانية من كاميرا معكوسة تحت الأرضية، فتنتج صورة الانعكاس.
- شيدر مخصص يرسم الرخام بدوال ضوضاء (noise) دون أي صورة: عروق عريضة، عروق دقيقة ذهبية، وخطوط البلاط.
- يُضاف الانعكاس فوق الرخام مع تمويه خفيف، وظل تحت السيارة، وحلقة الضوء.

### 5.4 الجزيئات (`buildParticles`)

1400 نقطة بمواقع عشوائية. الشيدر يحركها ببطء للأعلى مع تمايل، ويجعلها تومض، وتكون ألمع قرب مركز الصالة.

## الخطوة 6: الحركة في كل إطار

**الملفات:** `src/runtime/index.js` (الدالة `frame`) و `src/runtime/timeline.js`

في كل إطار (نحو 60 مرة في الثانية):

1. **قراءة التمرير:** `progress = scrollY / أقصى تمرير`، رقم من 0 إلى 1، مع تنعيم.
2. **حساب القيم:** `timeline.evaluate(progress)` تمر على المسارات الـ12 وتحسب قيمة كل خاصية بين مفتاحين مع منحنى تسارع (`sampleTrack`).
3. **الكاميرا:** موضعها يُحسب من الزاوية والارتفاع والمسافة. يُضاف إليها الدوران التلقائي مضروباً في `camera.orbit`: يساوي 1 في الصالة (الكاميرا تدور)، و0 عند المواصفات (الكاميرا تثبت على اللقطة).
4. **بقية الخصائص:** شدة أعمدة الضوء، شفافية الجزيئات، التعريض، حلقة الأرضية، مصابيح السيارة.
5. **النصوص:** `content.update(progress)` تُظهر القسم الذي يقع التمرير داخل مداه وتخفي الباقي.
6. **الرسم:** `renderer.render(scene, camera)`.

اللقطات حسب نسبة التمرير:

| التمرير | القسم | اللقطة |
| --- | --- | --- |
| 0 – 0.13 | الصالة | الكاميرا تدور حول السيارة |
| 0.20 – 0.36 | التصميم | لقطة قريبة للمقدمة |
| 0.44 – 0.60 | الأداء | منظر جانبي، أرقام على اليمين |
| 0.68 – 0.83 | الأبعاد | منظر علوي من الخلف |
| 0.90 – 1 | الطلب | منظر خلفي، والدوران يعود |

الخصائص التي يُسمح للخطة بتحريكها قائمة ثابتة: `camera.azimuth`، `camera.elevation`، `camera.radius`، `camera.fov`، `camera.orbit`، `camera.frame`، `camera.target.x|y|z`، `environment.exposure`، `environment.reflections`، `beams.opacity`، `particles.opacity`، `floor.reflectivity`، `floor.ring`، `subject.lamps`، `lights.<id>.intensity`.

## كيف تضيف مجسّماً جديداً (مثلاً SUV)

1. اكتب دالة بناء `buildSuv(subject, theme)` ترجع `{ object, footprint, setLamps }`، أو حمّل ملف `.glb` داخلها.
2. سجّلها في `src/runtime/index.js`: `const ASSETS = { coupe: buildCoupe, suv: buildSuv };`
3. أضف الاسم في `plan/scene-plan.schema.json`: `"asset": { "enum": ["coupe", "suv"] }`
4. أضف قاعدة في `planner/rules.mjs` تطابق كلمة `suv` وتكتب `plan.scene.subject.asset = 'suv'`.

بعدها يكفي أن يكتب المستخدم "SUV" في الطلب.

## حدود النظام

- المخطِّط يفهم فقط مفردات قواعده العشر، بالإنجليزية أو بالعربية. أي طلب آخر (مثل "قطة تلعب بالحديقة") يظهر في `meta.unresolved` ولا يُنفَّذ، لأن المشغّل لا يملك مجسّم قطة ولا حديقة.
- نصوص الصفحة (العناوين والمواصفات) إنجليزية حتى مع طلب عربي.
- يوجد مجسّم واحد (`coupe`) وصالة واحدة (`showroom`) وأرضية واحدة (`marble`).
- السيارة شكل مبسّط من معادلات، وليست نموذجاً حقيقياً مفصّلاً.
- يمكن استبدال المخطِّط بنموذج لغة (LLM) يُخرج الخطة مباشرة، بشرط أن تمر من الفحص نفسه. هذا لم يُبنَ بعد.

## الأوامر

```bash
npm run plan     # يحوّل plan/brief.txt إلى plan/scene-plan.json ويطبع ما فهمه
npm run plan:ar  # الشيء نفسه للطلب العربي plan/brief.ar.txt
npm run check    # يتأكد أن الخطتين صالحتان ومطابقتان للطلبين
npm start        # يشغّل الموقع على http://localhost:8124
```

روابط مفيدة للتجربة: `?p=0.52` يثبّت التمرير عند نسبة معينة، و `?plan=name` يحمّل خطة أخرى من `plan/name.json`.
